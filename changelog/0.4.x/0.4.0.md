# 0.4.0 — 2026-11-25

## Added

- **Footnotes on `unhcr_get_asylum_applications` and `unhcr_get_asylum_decisions`** ([#22](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/22)) — `footnotes` and `footnotes_total`, matched on UNHCR's ASY caveats, so the USA 2024 half-year note reaches an application or decision series.
- **String lists** ([#23](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/23)) — `stages`, `decision_levels`, `population_types`, and `split_by` accept a string of codes (`"N"`, `"N, R"`), and `split_by` folds case. `UNHCR_NORMALIZE_INPUTS=false` turns both off and rejects them.
- **Common English country names** ([#24](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/24)) — `name_contains` returns the one country for a name UNHCR spells otherwise (`turkey`, `burma`, `ivory coast`, `uk`). `origin` and `asylum` still refuse a name; the hint now gives its ISO3 (a multi-word name only as a list entry).
- **`serverInfo.description`** — `initialize` carries the server's description (framework).

## Changed

- **`unhcr_dataframe_query` (breaking)** — SQL that 0.3.0 answered now fails `system_catalog_access`; rename the alias, CTE, or other name:
  - **35 names, refused as identifiers** in any case, quoted or not: `duckdb_{columns,constraints,databases,indexes,logs,schemas,tables,types,views}`, `pragma_database_list`, `sqlite_{schema,temp_master,temp_schema}`, and `pg_{am,attrdef,attribute,class,collation,constraint,database,depend,description,enum,index,indexes,namespace,prepared_statements,proc,sequence,sequences,settings,tables,tablespace,type,views}`. Roles: column alias (bare, quoted, uppercase, without `AS`), CTE name, table alias, derived column, subquery alias, `VALUES` column list, window name, struct key, lambda parameter. (`sqlite_master` was already refused.)
  - **The same names as a whole word inside a longer quoted identifier** (`"pg_class count"`, `"pg_class.id"`); `"x_pg_class"` and `"pg-class"` still answer.
  - **An `E'…'` literal continued by another literal on a later line** now refuses the query when a denied-function or catalog name follows in a later literal or comment. A plain `'a'` continued on a later line and a one-line `E'a'` still answer.

  Names inside ordinary string literals and comments still answer.
- **`unhcr_dataframe_query` reasons** — `PIVOT` without `IN` → `non_select_statement`; a bare metadata-view reference → `system_catalog_access`; `SHOW`/`DESCRIBE` of a missing table → `missing_table`; a quoted path such as `"a/b"` → `non_select_statement`; unparsable `VALUES` → `invalid_sql`. `range()` and `generate_series()` over constants now answer.
- **Asylum footnotes** ([#22](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/22)) — an asylum call now fails when `/footnotes/` cannot be read, as in the other data tools.
- **`name_contains` initials** ([#24](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/24)) — a period between two single characters joins them (`U.K.` reads `uk`); any other period is a space. Initials read letter by letter only when the query matches nothing with them joined (`F.R. Germany`).
- **Startup** — refuses Node below 24 and a malformed `MCP_HTTP_ENDPOINT_PATH` or `MCP_PUBLIC_URL` (framework).
- **Framework guidance** — skills and packaging scripts re-synced; `engines.bun` >=1.4.4.

## Fixed

- **Concurrent first stagings** ([#25](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/25)) — every staged table lands on one canvas and stays queryable, where all but one failed `missing_table`. A replaced canvas's leftover metadata and eviction races between concurrent stagings are fixed with it.
- **Empty `/countries/`, `/regions/`, or `/footnotes/` list** — retried, never cached, and fails the call if it persists; it read as "none" for 24 h.
- **Cancelled calls** — a cancelled call can no longer end the server process.
- **Staging eviction** — a call cancelled while it evicts no longer leaves a listing for a dropped dataframe.
- **`unhcr_dataframe_describe`** — reports DuckDB's column types for a `register_as` table; a `SUM` was listed as VARCHAR.
- **SQL engine load failure** — the client-visible log line is fixed text, and the engine's message goes to the server log.
