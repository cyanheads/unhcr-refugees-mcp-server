# 0.2.0 — 2026-10-20

## Changed

- **SQL compatibility (breaking)** — framework adoption rejects previously successful `current_setting('threads')`, `current_schema()`, `current_schemas(true)`, two-argument `in_search_path('memory','main')`, `query_table` over an existing staged table, and `query()` with a nonliteral argument; reference staged tables directly.
- **Display requests** — shared `limit` and SQL `preview` accept integers through 1,000,000, clamp to 500 and `row_limit` respectively, and disclose requested and effective values alongside other notices ([#14](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/14)).
- **Framework guidance** — sync API references, authoring and release skills, and framework-pattern checks; retain gated release review.
- **Skill versions** — `add-tool` 2.33 → 2.34; `api-auth` 1.5 → 1.6; `api-canvas` 2.6 → 2.8; `api-config` 1.24 → 1.26; `api-context` 2.10 → 2.12; `api-errors` 1.19 → 1.23; `api-linter` 1.21 → 1.22; `api-mirror` 1.4 → 1.5.
- **Skill versions** — `api-telemetry` 1.17 → 1.21; `api-testing` 1.14 → 1.15; `api-utils` 2.15 → 2.18; `design-mcp-server` 2.31 → 2.32; `field-test` 2.19 → 2.22; `git-wrapup` 1.28 → 1.30; `polish-docs-meta` 2.22 → 2.23; `security-pass` 1.12 → 1.13; `tool-defs-analysis` 1.7 → 1.8.

## Fixed

- **Source completeness** — SQL results and saved descendants retain `complete` and original `incomplete_sources` independently of display truncation, including nested literal queries and expired ancestors ([#10](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/10)).
- **SQL result size** — serialized tool results stay within 65,536 UTF-8 bytes across both surfaces; withheld rows and metadata remain retrievable as ordered base64 JSON chunks, preserving exact values and saved tables ([#11](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/11)).
- **Dataframe startup** — an empty `CANVAS_PROVIDER_TYPE` selects DuckDB as documented.
- **Desktop bundle** — explicitly disable unavailable native dataframes and exclude tests and Vitest configuration from the portable bundle.
