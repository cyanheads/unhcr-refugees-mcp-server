# 0.3.0 — 2026-11-04

## Added

- **Agent skill** — `skill://unhcr-refugees-guide/SKILL.md`, the server's first, served over MCP and shipped in the npm package, Docker image, and `.mcpb` bundle; `instructions` points to it.
- **`UNHCR_CLAMP_LIMITS`** — `false` rejects an over-cap `limit`, `preview`, or `row_limit` at the schema instead of serving the cap ([#16](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/16)).
- **Agent Plugins manifests** — root `plugin.json` and `mcp.json`.

## Changed

- **Count inputs** ([#16](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/16)) — `limit` defaults to 25 (cap 2,000), `preview` to 25 (cap 1,500 or `row_limit` when lower), and `row_limit` to 1,000, or `CANVAS_DEFAULT_ROW_LIMIT` when lower (also its cap). A larger value is served at its cap with a notice, a log line, and a counter.
- **`unhcr_dataframe_query` (breaking)** ([#16](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/16)) — the 65,536-byte result budget is removed and rows up to `preview` are served whole; `result_chunks`, `metadata_withheld`, and the `result_storage_unavailable` reason are gone.
- **Withheld-row guidance** ([#16](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/16)) — a notice never offers a count already at its ceiling: `unhcr_dataframe_query` names `row_limit` when it capped the result, otherwise `preview` up to the lower of 1,500 and `row_limit`, then paging with `LIMIT` and `OFFSET`; the data tools drop "raise limit" once `limit` is 2,000.
- **Deployments without dataframes** ([#16](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/16)) — `CANVAS_PROVIDER_TYPE=none`, the `.mcpb` bundle included, show 25 rows by default (was 100); raise `limit` for the rest.
- **Country filters** ([#20](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/20)) — `origin` and `asylum` accept up to 250 distinct codes (was 50), enough to list every country; more fails `too_many_country_codes` before any upstream request.
- **Server instructions** — state the 25-row default and the clamp, place stateless people under origin `XXA`, and point to the skill.
- **Packaging** — `.mcpbignore` excludes build-only root paths, `lint:packaging` checks it with the plugin manifests and `skills/`, and `clean-mcpb` strips more build-only package files from the bundle while keeping the MCP SDK's runtime `dist/ext/skills/` modules.
- **Framework guidance** — 25 skills re-synced and `add-skill` 1.0 added; the bug report form takes one Environment table; `bunfig.toml` `minimumReleaseAge` is 1 day (was 3).

## Fixed

- **`CANVAS_DEFAULT_ROW_LIMIT` below 1,000** ([#16](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/16)) — every SQL call that omitted `row_limit` failed; the default now follows the cap.
- **Footnote cap** ([#17](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/17)) — `unhcr_get_population`, `unhcr_get_demographics`, and `unhcr_get_solutions` rank caveats against the inline cut: those on inline rows first, then country-specific before general, then by the first row each matches, then UNHCR's order.
- **Population nowcast** ([#18](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/18)) — `include_nowcast` rows are sorted, cut at the effective `limit`, and staged as their own dataframe when they overflow or `stage` is set, including when the window starts after the latest year-end figures; new `nowcast_total` and `nowcast_dataset` report the count and the table.
- **Call deadline** ([#19](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/19)) — the `Timeout` is `retryable` with a resume hint when the response cache can hold a full upstream page (`UNHCR_CACHE_MAX_MB` 4 or more).
- **Dataframe startup** — a blank or unsubstituted `${…}` `CANVAS_PROVIDER_TYPE` reads as unset and selects DuckDB.
