# 0.1.1 — 2026-09-26

## Added

- **`unhcr_list_reference`** — decodes the input vocabulary per `topic`: `countries`, `regions`, `coverage` (each dataset's first and latest year, plus the nowcast month), `population_types`, `asylum_codes`. `name_contains` resolves a country name to ISO3; a query with no Latin letter or digit matches nothing ([#6](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/6)).
- **`unhcr_get_population`** — year-end stocks from 1951 (refugees, asylum-seekers, `oip`, IDPs, stateless, others of concern, host community) plus in-year returns. `unrwa_refugees` and `idmc_conflict_idps` join as separate columns where those series report, including years UNHCR does not ([#5](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/5)); `include_nowcast` adds UNHCR's current-year estimate by asylum country.
- **`unhcr_get_demographics`** — year-end stocks from 2001 by population type, sex, and age band, with `disaggregated` and `sex_disaggregated_share`; bands are null where UNHCR has no breakdown. `population_types` filters.
- **`unhcr_get_asylum_applications`** — applications lodged from 2000, split by application stage by default (`split_by`, `stages`); counts of cases are never added to counts of persons.
- **`unhcr_get_asylum_decisions`** — decisions from 2000 by outcome, with `refugee_recognition_rate` and `total_protection_rate` computed from summed counts over `substantive_decisions` (`split_by`, `decision_levels`).
- **`unhcr_get_solutions`** — refugee returns, resettlement, naturalisation, and IDP returns from 1959.
- **Scope inputs** — the five `unhcr_get_*` tools take ISO3 `origin` / `asylum`, up to 50 codes each: ISO2 is rewritten, a JSON-stringified list reads as its codes ([#2](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/2)), and a UNHCR code fails `unknown_country_code` with the ISO3 to pass. `expand` lists every country of an unfiltered dimension; year bounds clamp to coverage.
- **Result fields** — every data result carries `measure` (stock or flow), `applied_scope`, `latest_year`, `complete`, `data_notes`, and `attribution` citing the UNHCR Refugee Population Statistics Database (CC BY 4.0). UNHCR's `"-"` is null, never zero; an empty result's notice says why, including when no row had a usable year ([#1](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/1)).
- **Footnotes** — population, demographics, and solutions return up to 20 matching UNHCR caveats with `rows_matched`, attached only to rows that carry one of the caveat's population types ([#4](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/4)).
- **Dataframes** — a result larger than `limit` (1–500, default 100), or any call with `stage: true`, is staged as a `df_XXXXX_XXXXX` DuckDB table with UNHCR and UN region columns. `unhcr_dataframe_describe` inspects it; `unhcr_dataframe_query` runs one read-only `SELECT` of up to 20,000 characters, and when `register_as` saved the result, the notice for withheld rows points at the saved table ([#3](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/3)).
- **Staging budget** — each tenant holds at most 1,000,000 staged rows; the oldest dataframes are evicted first and named in `evicted`. Listing dataframes is off over HTTP with `MCP_AUTH_MODE=none`.
- **`unhcr_dataframe_drop`** — drops a dataframe before its TTL; registered disabled unless `UNHCR_DATAFRAME_DROP_ENABLED=true`.
- **UNHCR client** — keyless; every request pins ISO3 matching (`cf_type=ISO`) and sends both year bounds. Requests are paced process-wide (two in flight), retried, cached, and collapsed when identical, within a 45 s budget per tool call; overload fails `upstream_busy` with `retryAfter`.
- **Configuration** — `UNHCR_REQUESTS_PER_SECOND` (default 4), `UNHCR_MAX_ROWS` (150000), `UNHCR_CACHE_MAX_MB` (64), `UNHCR_DATASET_TTL_SECONDS` (86400), `UNHCR_DATAFRAME_DROP_ENABLED` (false). `CANVAS_PROVIDER_TYPE` defaults to `duckdb`; `none` turns dataframes off.
- **Distribution** — npm package (stdio or Streamable HTTP), a `linux/amd64` + `linux/arm64` image on GHCR, a Claude Desktop `.mcpb` bundle (no DuckDB binding, so the data tools answer inline only), and Claude Code and Codex plugin manifests. No resources or prompts.
- **Docker image** — production dependencies install on the build platform with `--os=linux --cpu=<arch>`, so each architecture carries its own DuckDB binding and no JavaScript runs under QEMU ([cyanheads/mcp-ts-core#575](https://github.com/cyanheads/mcp-ts-core/issues/575)).

## Dependencies

- `@cyanheads/mcp-ts-core` ^0.13.8, `@duckdb/node-api` ^1.5.5-r.5 (dataframe engine), `pino-pretty` ^13.1.3, `zod` ^4.6.5.
