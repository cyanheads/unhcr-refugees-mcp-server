# 0.5.0 — 2026-11-27

## Added

- **`reporting_periods`** identifies December and June UNHCR stocks, annual and first-half flows, and separate UNRWA, IDMC, and monthly nowcast periods. Ambiguous vintages are marked unverified. Staged tables and saved SQL results retain source periods. ([#26](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/26))
- **`UNHCR_NORMALIZE_INPUTS`** accepts canonical numeric and boolean strings in typed fields when enabled. Advertised input schemas stay the same. ([#27](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/27))

## Changed

- **Breaking — `unhcr_dataframe_query`** now yields `sql_execution_error` for integer or DECIMAL `//` or `%` by zero. Use `TRY(...)` to return NULL. Floating-point `/` retains its behavior.
- **`unhcr_dataframe_query`** accepts `ROWS` as an implicit column alias, as in `SELECT 1 rows`.
- **`unhcr-refugees-guide` 1.2** explains when to read reporting periods and footnotes before comparing years.

## Fixed

- **Reference reads** can serve validated countries, regional bureaus, and footnotes for up to seven days from their last successful load during transient refresh failures. They report the list’s age and apply a refresh cooldown. Coverage and nowcast are excluded. ([#28](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/28))
- **Shared upstream reads** honor each caller’s deadline and cancellation. A caller with time left can join a single replacement fetch after the shared request’s deadline. ([#29](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/29))
- **Dataframe scratch failures** surface `canvas_scratch_unavailable` with operator guidance. Once the scratch path is writable, the same server process can query and stage again. ([#30](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/30))
- **Transient upstream failures** that exhaust retries return `ServiceUnavailable` with `retryable: true` and guidance to wait briefly and retry. ([#31](https://github.com/cyanheads/unhcr-refugees-mcp-server/issues/31))
